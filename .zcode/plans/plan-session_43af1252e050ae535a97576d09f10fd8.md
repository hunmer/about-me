【实现方案】

1. 扩展记忆库元数据模型
   - 修改 `lib/plugins/openai/aliveness/models/memory_library.dart`，新增可选字段：
     - `description`：库用途说明，默认空字符串。
     - `allowedKeyPrefixes`：允许 AI 写入的 key 前缀列表，默认空列表表示不限制。
   - 更新 `toJson/fromJson`，对缺失字段提供默认值，保证已有 `memory_libraries.json` 可直接读取。
   - 前缀采用点分命名空间语义：`user` 匹配 `user` 和 `user.xxx`，但不匹配 `username`；写入前统一 trim、去空、去重并校验格式。

2. 扩展记忆库创建与维护
   - 修改 `AlivenessStore.createMemoryLibrary`，支持传入说明和允许前缀，并将其写入库索引。
   - 增加更新记忆库元数据的方法，供管理界面编辑已有库；更新操作沿用现有 `_libraryWrites` 串行写入，避免并发覆盖其他库。
   - 在记忆库管理界面的创建/编辑对话框中增加说明输入和允许前缀输入（逗号或换行分隔），列表页展示说明及限制摘要，并支持打开已有库编辑元数据。

3. 在服务层集中执行写入限制
   - 在 `MemoryService` 增加按库加载和校验写入策略的方法。
   - `upsertForTool/updateByKey` 的共同入口 `_writeByKey` 在实际写入前校验 key；规则为空放行，规则不匹配时抛出明确的 `ArgumentError`，包含目标库和允许前缀信息。
   - 对自动记忆提取的 `mergeFragments` 增加同一规则校验，使 LLM 自动提取不会绕过库限制；手动管理页写入继续允许任意合法 key，避免管理员无法维护历史数据。
   - `saveFragments` 不对已有全量数据强制套用白名单，避免旧库中已存在的 legacy/历史 key 因新增规则而无法保存；删除、查询和枚举保持原行为。
   - 保持点分前缀边界匹配，确保 `user` 不会误放行 `username`。

4. 让 AI 能看到规则和库说明
   - 扩展 `buildLibraryContext`，向 Agent 明确每个库的用途、允许写入前缀以及空规则代表不限；要求写入前先按该规则选择 key。
   - 扩展自动提取 prompt，注入说明和允许前缀，要求输出仅使用允许命名空间；服务层校验作为最终保障。
   - 更新原生 memory tool 的 `add_memory/update_memory` 描述，以及 `lib/plugins/agent_chat/tools/memory.json` 中对应契约文案，让 JS tool 和原生 tool 都能获得相同提示。无需给 tool 增加新的运行时参数。

5. 增加回归测试
   - 模型序列化/反序列化：缺少新字段的旧 JSON、说明保存、前缀保存。
   - 服务写入：空规则放行；`user` 允许 `user.name` 但拒绝 `username`/`event.x`；更新和新增都校验；错误信息可识别。
   - 自动合并：不匹配前缀的提取结果不写入，匹配结果正常写入；手动写入仍可维护不匹配的历史 key。
   - 管理库元数据创建/更新及现有 UI 测试的兼容性。
   - 运行格式化、相关 Flutter/Dart 测试和静态检查，确认未影响既有记忆库查询、迁移和多库隔离测试。
