## 目标

完成两组手机 Flutter 端改动：

1. 插件切换时保留首页（或启动恢复闸门），清理当前插件及其子页面，进入新插件，避免旧插件路由持续保活。
2. WebView 浏览器页面销毁时释放 JS Bridge、批处理 Timer、延迟诊断任务和 TabManager 中对应的 controller 引用，同时保留标签页的 URL/title 等持久化数据。

保留当前工作区已有的 Watch App 和 docs 改动，不覆盖、不重置它们。

## 实现步骤

### 1. 统一带路由名的平台路由创建

修改 `lib/core/navigation/navigation_helper.dart`：

- 给 `pushReplacement` 增加可选 `routeName`，将 `RouteSettings(name: routeName)` 同时传给 iOS 的 `CupertinoPageRoute` 和其他平台的 `RouteHelpers.createRoute`。
- 扩展 `pushAndRemoveUntil`，增加可选 `routeName`，通过 `RouteHelpers.createRoute` 创建目标路由并保留 `/plugin/<id>`。
- 保持现有平台行为：iOS 保留侧滑返回，非 iOS 继续使用项目的零时长路由，避免改回普通 `MaterialPageRoute`。

### 2. 将 `PluginManager.openPlugin` 改为插件栈替换

修改 `lib/core/plugin_manager.dart`：

- 保留 `replaceCurrent` 参数以兼容现有调用方，但默认改为启用替换策略。
- 仍然先拒绝当前已经处于同一插件主路由的重复打开，并保留 `recordPluginOpen`、插件路由名和 onboarding 行为。
- 当当前上下文属于插件主路由或插件子页面时，使用带 `routeName` 的 `pushAndRemoveUntil`：
  - `/jelly_home` 及 `/jelly_home/<tab>` 作为保留边界；
  - `/startup` 作为冷启动恢复场景的保留边界；
  - 如果栈中没有上述边界，则清理旧栈后让新插件成为根路由，避免旧插件根路由残留。
- 当从首页或普通非插件页面打开插件时，仍然推入目标插件，保留首页返回路径。
- 目标效果覆盖：`[首页,A] -> [首页,B]`、`[首页,A,详情] -> [首页,B]`、`[startup,A] -> [startup,B]`。
- 继续通过统一导航 helper 创建路由，移除现有 replacement 分支直接构造 `MaterialPageRoute` 的不一致行为。

### 3. 修正插件路由上下文识别和旋转启动器兼容性

修改 `lib/core/route/route_history_manager.dart`：

- 调整插件路由跟踪：无名的插件详情页/自定义页面不再立即清空当前插件标记；有名字且没有插件归属的普通页面仍会清空标记，避免把全局设置页误认为插件子页。
- 保持正式 `/plugin/<id>` 和通过 `markNextRouteAsPlugin` 登记的自定义路由归属逻辑。
- 增加或复用定向查询接口，让 `openPlugin` 能识别正式插件子页和无名插件子页，而不依赖最后一次打开插件的历史字段。

修改 `lib/screens/rotary_plugin_launcher_screen.dart`：

- 删除“打开插件后再手动 `removeRoute` 启动器路由”的旧流程。清栈式插件替换已经会移除启动器，避免对已移除 Route 再次调用 `removeRoute`。
- 保留同插件只返回的快捷路径。

不修改独立 Navigator 的浮窗插件窗口，也不把首页小组件的 `openContainerWithHero` 等独立导航路径强行改成根 Navigator 的清栈逻辑；本次范围是统一 `PluginManager.openPlugin` 入口。

### 4. 完善 TabManager 的 controller 脱离 API

修改 `lib/plugins/webview/services/tab_manager.dart`：

- 增加按 tab ID 和 controller 身份校验的清理方法，例如 `clearController(tabId, expectedController)`。
- 只有当前 map 中仍是同一个 controller 时才移除，防止旧 WebView 的异步销毁回调误删同一 tab 后重新创建的新 controller。
- 不调用 `controller.dispose()`；原生 controller 的所有权仍由 `InAppWebView` 子树销毁流程负责。
- 不在浏览器页面退出时调用 `closeAllTabs`，保留标签页元数据，以便重新进入时重建 WebView。

### 5. 完善 WebView 标签内容的释放链

修改 `lib/plugins/webview/screens/webview_browser_screen.dart`：

- 在 `_WebViewTabContentState` 保存当前 `InAppWebViewController`。
- 在 `onWebViewCreated` 先保存 controller，再写入 `TabManager` 并初始化 JS Bridge。
- 增加 `dispose()`：
  - 取消并清空延迟诊断 Timer；
  - 调用 `_jsBridgeInjector?.dispose()` 并清空引用；
  - 调用 TabManager 的身份校验清理方法；
  - 清空重定向集合和 controller 字段；
  - 最后调用 `super.dispose()`。
- 将 `onLoadStop` 中销毁后仍可能执行的延迟 `evaluateJavascript` 改为可取消 Timer，并在异步回调完成后检查 `mounted`。
- 对 `_initializeTab()` 的所有异步创建路径增加 `mounted` 检查：如果页面在 `createTab` 完成前已经销毁，关闭本次由页面新建且尚未挂载的 tab；如果已经正常挂载，则退出页面时只释放运行时 WebView，不删除标签数据。
- 对 `setState`、异步导航状态查询和页面回调增加必要的存活检查，避免退出后继续访问 State 或已销毁 controller。

修改 `lib/plugins/webview/services/js_bridge_injector.dart`：

- 让 `dispose()` 可重复调用且完整释放：取消 30 秒统计 Timer、销毁 `BatchRequestExecutor`、清空 `_context` 和执行器引用。
- 初始化或统计回调遇到已释放实例时直接返回，避免页面退出后的 Timer/异步任务继续工作。

### 6. 增加定向验证

新增或更新测试：

- 插件导航 Widget 测试：用 `GlobalKey<NavigatorState>` 和轻量命名页面断言完整路由栈，覆盖首页打开插件、插件主页面切换插件、插件深层页面切换插件，以及启动恢复栈；确认首页/启动闸门保留、旧插件路由被移除、目标路由仍带 `/plugin/<id>`。
- 路由历史测试：覆盖无名插件子页不会丢失插件归属，普通命名页面仍能结束插件上下文。
- TabManager 生命周期测试：覆盖创建 tab 后 controller 脱离、身份不匹配时不误删新 controller、关闭 tab/关闭全部 tab 的既有行为不变。
- JS Bridge/WebView 的可测试部分覆盖 dispose 后 Timer 和批处理器不再保留；平台 WebView controller 不直接由业务层 dispose。

最后运行定向 `flutter analyze` 和相关 `flutter test`，根据编译和测试结果修正实现；不进行真机耗电测量或 Watch App 构建，因为本次范围明确是手机 Flutter 端。
