【用户意图】所有原“视频模式”入口统一使用精灵图，不保留视频播放或回退；本地视频只保留 WebM，并加入 Git 忽略。

【假设】本次需求取代此前“仅单动作原型”的范围：补齐全部 106 个动作，每个动作独立一张 PNG。沿用已验证的 192×108、12 fps 参数；现有区域、绑定、动作 ID 和档案不丢失。界面称为“精灵图”，档案内部暂保留 displayMode='video' 等存储键，避免无关迁移。

【实施方案】
1. **完成全部精灵图资源。** 使用 PowerShell 7 和 FFmpeg libvpx-vp9 解码现有 106 个 WebM，保留 Alpha。改进脚本以实际采样输出帧数生成网格，10 列、按动作自动计算行数，避免按时长估算而漏帧或播放空格。每个动作输出独立 PNG、JSON 元数据，默认 manifest 写入图片路径、帧尺寸、列数、行数、有效帧数及 fps；保留许可与来源，更新资源校验清单。
2. **统一播放器。** 保留 VideoPetPlayer 的现有调用接口和纯 Dart 播放状态机，内部全部换成 flutter_spritesheet_animation；编辑器、主页、设置页共用同一实现。支持点击/手动动作播放一次、结束后恢复 hover/idle，保留 generation 防串播、重复点播、暂停、生命周期和错误重试。使用 Flutter 指针事件复用 contain 坐标转换，保留区域拖动、缩放、悬浮、点击和右键操作。图片按当前动作加载，移除旧动作的不必要缓存，避免预载全部纹理。
3. **调整 JSON 与导入。** 增加明确的 spritesheet 配置和校验，JSON/ZIP 导入只要求运行时图片资源，并使用正确 image/png MIME 与现有持久化机制。已有内置 dsh-pet 视频档案通过动作 ID 补齐默认精灵图配置，保留用户区域和绑定；旧自定义纯视频包提示需转换，绝不调用视频回退。
4. **移除旧路线。** 删除编辑器的视频/精灵图样例切换及硬编码单动作预览，全部走统一播放器。清理该功能专用的 WebView/HTML video Surface、视频资源 HTTP server 及对应过时测试；不删除项目其他功能仍使用的 WebView/视频依赖。
5. **整理本地资源与 Git。** 检查并删除该素材包中的 106 个 MOV；保留 106 个 WebM 作为本地转换源。在根 .gitignore 添加仅针对该素材包 WebM 目录的规则。移除 pubspec 中 WebM/MOV 的 assets 声明，应用仅打包精灵图及配置。确认视频目前均未跟踪，无需修改 Git 索引；保留原始来源和必要许可信息。
6. **文档与验证。** 更新使用说明、资源说明和测试，移除“双格式视频/原型回退”的描述；检查 106 张 PNG 的透明通道、尺寸、有效帧数和 manifest 引用一致性。定向测试覆盖 manifest、图片导入/持久化、旧内置档案迁移、区域坐标、播放优先级、暂停恢复与结束回调，并运行相关 Dart 静态分析。确认 git check-ignore 命中 WebM、MOV 已删除且 pubspec 不打包视频。

【验收标准】
- 106 个动作都有各自独立 PNG，默认 manifest 不再以 WebM/MOV 作为运行来源。
- 编辑器、主页和设置页均使用 Flutter 精灵图展示；缺图只报错，不启动 WebView 或视频播放器。
- 原有区域交互、动作顺序/随机、结束恢复和暂停行为保留。
- 本地仅保留 WebM 源视频，WebM 被 Git 忽略且不进应用包，MOV 删除。
- 定向测试和静态分析通过，报告实际 PNG 总体积及最大纹理解码开销。
- 按工作区约定不自动使用真实浏览器，不宣称五个平台已完成真机验收。
