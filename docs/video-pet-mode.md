# Live2D 插件的精灵图模式

## 使用

1. 打开 Live2D 插件，新建或编辑档案，将展示模式切换为“精灵图”。已有视频模式档案也统一使用精灵图渲染；首次切换自动载入默认 dsh-pet 资源包。
2. 点击“编辑交互区域”。在“编辑”模式框选区域，选择区域后可拖动，拖动右下角调整大小；也可输入归一化坐标、名称和优先级。
3. 配置全局及每个区域的点击动画，可多选并选择随机或顺序播放。区域“继承全局”开启时使用全局绑定；关闭后清空动作表示禁用该事件。旧 `hover` 字段保留兼容，播放器不再通过鼠标悬浮切换动作或进入 busy，编辑器隐藏悬浮动画配置。
4. 切到“测试”模式，移动鼠标、点击各区域，检查显示的区域和动作。触屏设备通过点击测试。保存编辑器，再保存档案。
5. 在主页选中该档案，或在设置页打开预览。动作资源列表可直接点播动作。
6. 编辑器的“随机移动”配置可分别选择左右移动、左右转向动画，并编辑速度、最短/最长等待时间；转向可以留空。默认 dsh-pet 使用“螃蟹走路”作为左右移动、“东张西望”作为左右转向。左右选择相同动作时，向左行走会自动镜像。

移动配置的 JSON 结构示例：

```json
{
  "movement": {
    "leftAnimationId": "螃蟹走路",
    "rightAnimationId": "螃蟹走路",
    "turnLeftAnimationId": "东张西望",
    "turnRightAnimationId": "东张西望",
    "dragAnimationId": "被鼠标拖拽悬空反馈",
    "speed": 40,
    "minIdleSeconds": 5,
    "maxIdleSeconds": 15
  }
}
```

7. 主页可直接拖拽宠物调整位置，位置在本机按模型保存。进入 Live2D 独立设置，在视频（精灵图）模式下可看到“随机走路”开关，默认关闭，保存在插件配置中；主页和预览同步生效。
8. Live2D 与视频模式默认保持全宽显示。精灵图全宽画布允许部分超出舞台边缘：限制画布中心在舞台宽度内移动，横向偏移范围为 `[-画布宽/2, 舞台宽-画布宽/2]`，初始居中，两端至少保留半幅画布。拖拽及随机走路使用同一边界，不缩小画布、不扫描像素；小尺寸角色仍保持整幅画布在舞台内。位置按边界区间归一化保存，窗口变化后按新边界恢复。
9. 编辑器“拖拽悬空”可配置 `movement.dragAnimationId`，留空表示不设置；默认绑定“被鼠标拖拽悬空反馈”。按住拖拽时优先于点播、点击和走路，松开或取消立即恢复当前交互或待机。旧内置档案仅在包含对应资源且未配置拖拽时补齐绑定，保留已有移动设置。

调试日志前缀为 `[VideoPetStage]` 和 `[VideoPetPlayer]`。舞台按状态变化输出模型、开关、移动范围和全部阻塞原因（`notLoaded/disabled/missingMovement/inactive/background/dragging/busy/noHorizontalSpace`），并记录等待秒数、目标、转向请求/完成/取消、走路和拖拽开始/结束；播放器记录 busy 原因、动作加载开始/成功/失败和完成 generation。日志不逐帧输出。

编辑器取消关闭不会修改已保存配置。设置页和主页的动作点播结束后，会恢复当前走路动作或待机。

## 唯一运行时与资源格式

编辑器、设置页和主页的全部动作统一使用透明精灵图，由 Flutter 按帧绘制，支持静态 WebP 和 PNG。没有 WebView、iframe、HTML 视频播放器或本地视频 HTTP 服务，也不会按平台回退到 WebM/MOV。暂停保留当前帧；切换动作、档案及前后台时需检查播放状态和资源释放。

默认 JSON 为 `assets/live2d/video/dsh_pet/manifest.json`，包含全部 106 个动作，每个动作使用独立有损 WebP 及同名 JSON 转换元数据。动作的 `sources.webp` 指向 WebP，自定义 PNG 包使用 `sources.png`；每动作只能有一种图片源。`spritesheet` 必须包含 `frameWidth`、`frameHeight`、`columns`、`rows`、`frameCount`、`fps`。运行时按 `frameCount` 播放有效帧，网格末尾的空白格不参与播放。

帧数以 FFmpeg 实际采样结果为准，不根据视频时长估算。默认保留源尺寸 640×360，恢复 12 fps、8 列。例如“东张西望”实际为 120 帧、15 行，纹理尺寸为 5120×5400；短动作实际 59 帧。逐张调节有损颜色和 Alpha 质量，确保每张严格小于 1,000,000 字节，透明背景保留，半透明边缘会量化。动作时长偏差不超过一帧（约 0.083 秒）。WebP 减少存储体积，最大单张纹理的 RGBA 像素数据仍为 105.469 MiB，切换时可能同时持有新旧图片，实际内存高于此值；运行时只按当前动作加载，不预载全部动作。该纹理超过 4096，低纹理上限设备尚需实机验收。

已存档案若引用内置默认 assets，会在播放前按动作 ID 刷新图片和网格参数，保留自定义区域、绑定及动作名称，避免旧版行列配置裁切新版图片。导入到独立目录或映射保存的 PNG 包继续使用自己的参数。

- 原生应用可导入 JSON 和同目录 WebP/PNG，或含唯一 `manifest.json` 的 ZIP；导入时复制资源到应用支持目录。
- Web 推荐导入 ZIP；单独 JSON 需要完整 HTTP(S)/data 图片资源地址。Web ZIP 的资源映射随档案持久化，较大的资源包会明显增加档案体积。
- 编辑器的 JSON 导入/导出用于配置交换，保留当前资源基址。导出的 JSON 不包含图片文件；移动到其它目录时需同时准备对应的相对路径资源。
- 旧自定义 WebM/MOV 视频包必须先在本地转换成 WebP/PNG 精灵图，再为每个动作填写 `sources.webp` 或 `sources.png` 和 `spritesheet`。仅保留视频源的自定义包不能直接播放，修改扩展名不能替代转换。
- 矩形区域相对整套角色画布配置，不随不同动作中的身体位移自动变化。重叠区域先比较优先级，再按列表顺序。

## 本地转换源与授权

默认包的 WebM 仅作为本地转换源保留在 `assets/live2d/video/dsh_pet/webm/`，由 Git 忽略，不提交、不打包；MOV 已删除。应用运行和自动化测试均不依赖这些 WebM 文件，转换元数据中的 `SourceVideoBytes` 只记录原始文件大小。

需要重新生成资源时，在具备 PowerShell 7、FFmpeg/ffprobe、cwebp 和本地 WebM 源的环境中运行 `scripts/convert_video_pet_spritesheet.ps1`，用 `-All` 转换全部动作；工具路径可通过 `-Ffmpeg`、`-Ffprobe`、`-Cwebp` 指定。转换后需同步核对 manifest、同名 JSON 元数据及图片，确保网格尺寸、实际帧数和帧率一致。

素材来自 https://github.com/PC2005-cloud/dsh-pet ，禁止商用，公开二创须保留原仓库署名；完整声明和固定来源版本见资源包 `NOTICE.txt` 与 `SOURCE-upstream.txt`。

## 验证范围与手动验收

自动化测试检查播放状态机、contain 坐标，以及默认 manifest 全部 106 张 WebP 的体积、尺寸、网格配置和 RGBA 透明度。透明与可见像素必须出现在有效帧内，不能用末尾空白格的透明像素代替。

Windows、Android、Web、iOS、macOS 共用精灵图渲染路径，但尚未完成五个平台的真机验收；测试通过不代表已验证各平台设备上的显示、交互或性能。各平台仍需分别执行以下步骤：

1. 新建精灵图模式档案，确认待机正常播放、人物边缘透明，画面没有黑色矩形。
2. 点击头部和身体，确认触发不同动作；桌面/鼠标设备悬浮、移动及移出时，确认不切换动作、不打断走路。触屏点击结束后应恢复当前走路动作或待机。
3. 新增两个区域并设置不同动作，保存后重新打开，确认区域和绑定保留；取消修改后再次打开，确认取消生效。
4. 调整窗口和角色尺寸，确认区域不漂移、画面留白不触发。快速点播不同动作并切换档案，确认没有旧动画返回或空白网格闪现。
5. 暂停编辑器，确认保留当前画面；切到其它页面或将应用放到后台，返回后确认可恢复。切回旧 Live2D 档案，确认模型与动作正常。
6. 导入包含 WebP/PNG 与网格配置的自定义包并点播；导入未转换的旧视频包，确认出现转换提示。
