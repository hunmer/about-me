## 架构速览（已落地）

- **代码位置**：`lib/plugins/openai/aliveness/`（模型/服务/编排/UI）+ `lib/plugins/agent_chat/services/aliveness_hook.dart`（agent_chat 版接入）+ `lib/plugins/agent_chat/controllers/chat_controller.dart`（sendMessage 分流）
- **双体系**：活人感同时接在 chat（频道 @AI，走 AlivenessOrchestrator）和 agent_chat（AI 对话，走 AgentChatAlivenessHook）——用户实际主要使用 agent_chat
- **agent_chat 流程**：发消息 → hook 接管 → 已读标记 → 缓冲（6-30s，"正在想"占位已移除）→ Jev 决策（DeepSeek 超时已放宽 5s/6s，失败回退本地规则）→ 延迟 → executeChain 生成（**隐藏窗口**：本轮 AI 消息对 UI 不可见，标题显示"● 正在输入中…"）→ 删原消息 + 写入最终形态（分条文本或纯语音，**一次性揭示** revealAlivenessMessages）→ 状态演化 + 记忆提取
- **记忆三层**：核心记忆常驻注入（权重 top3，解决"问我的兴趣不知道"）+ 话题激活联想（tag 子串匹配）+ `search_memory` 工具（LLM 按需查，agent 需开 enableFunctionCalling）
- **语音**：TTS 插件新增 synthesizeToFile（http/minimax 支持，system 不支持）；agent_chat 以 FileAttachment.audio 附件裸露渲染（无气泡框）；chat 以 MessageType.audio；决策 useVoice 时**只发语音不发文本**（合成失败回退文本）
- **数据**：`app_data/openai/aliveness/<agentId>/{state.json,stats.json,decisions.log,memory/}`；全局 Jev 配置 `aliveness/settings.json`；开关挂在 AIAgent.alivenessConfig（编辑页 UI 全量可配）

- **Jev API 真实格式**（曾踩坑，官方文档 docs.typesafe.ai）：`POST https://api.typesafe.ai/v1/systemone`，state 为**字符串**、问题字段为 **instructions**、choice 的 criteria 为选项描述映射、score 的 criteria 为等级数组；响应 score 是 0~N-1 索引需归一化
- **DeepSeek 限制**：不支持 response_format json_schema（HTTP 400），tool_orchestrator 已按 baseUrl 含 deepseek 降级 json_object + 提示词约束；deepseek-flash 是推理模型，reasoning 占 token，maxLength 需 ≥2000
