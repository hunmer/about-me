## 架构速览（已落地）

- **代码位置**：`lib/plugins/openai/aliveness/` + `lib/plugins/agent_chat/services/aliveness_hook.dart` + `chat_controller.dart`（sendMessage 分流）

## 本会话修复的坑（重要，勿回退）

1. **空工具列表 JSON 泄漏**（旧路径）：json 格式锁死下模型无法同时输出内容，空工具时必须丢弃 JSON 无格式重新生成（`_executePlainResponse`）；onToken 以 `{` 开头的前缀不显示防半截泄漏
2. **DeepSeek thinking 400**：`reasoning_content` 必须回传，dartantic 不回传 → `DeepSeekCompatClient`（http.BaseClient）拦截请求注入 `thinking:{type:disabled}`（仅 deepseek 域名）；经 `AppOpenAIProvider`（重写 createChatModel 传 client）注入。e2e 已实测通过
3. **工具描述 pluginId ≠ JS API 插件**：moments.json/memory.json 的方法挂在 openai 命名空间 → `JSBridgeManager.resolvePluginApi`（API 名注册表，精确匹配 miss 后全局搜方法名）；`_pluginApiNames` 为 **nullable（热重载防御**：新字段初始化器不作用于已存在单例，曾致 NoSuchMethodError → FC 回退）
4. **setResult 嵌套删除**：evaluate wrapper 的 `delete globalThis.setResult` 会删掉外层正在用的（生图内层 evaluate 跑完后外层调用报 ReferenceError）→ wrapper 改闭包局部 const setResult + 条件清理（`globalThis.setResult === setResult` 才删）
5. **MessageService 双实例覆盖**：ChatScreen 每次自建 MessageService（`chat_screen.dart:173`），与插件级单例双写同一文件互相覆盖（图片消息被抹）→ `MomentsService.currentMessageService` 由 ChatController.initialize 注册，发送时优先用它
6. **QuickJS 大 base64 卡顿**：MB 级 base64 每次过桥=主线程 JSON/JS 解析几百 ms → v1.3.4 路径化传输（见上）
7. **日志刷屏**：`_clipForLog`（mobile_js_engine）超 300 字符截断；应用于调用参数/Future 结果/错误 JSON 三处
8. **JS 工具执行超时**：`ToolService.executeJsCode` evaluate 60s→5 分钟（生图轮询最长 4 分钟）
9. **工具文件增量同步缺口**：`_syncMissingToolFiles` 只补缺失文件——**新增工具必须用新文件名**（moments.json 因此而生）；修改已有文件到不了老安装（本次靠手动同步用户本地副本 + index.json）
