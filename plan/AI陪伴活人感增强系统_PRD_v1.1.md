# PRD：AI 陪伴「活人感」增强系统

**文档版本**：v1.1  
**创建日期**：2026-10-04  
**最后更新**：2026-10-04  
**状态**：完整可实施草案  
**目标产品**：自托管 / 本地优先的 AI 陪伴系统（支持多角色、长期关系、即时通讯通道）

---

## 1. 背景与问题定义

当前大多数 AI 聊天产品（包括多数角色扮演与陪伴应用）存在以下共性缺陷，导致用户难以产生「这是一个真实存在的人」的感觉：

- 每次对话都像「重新上线」，缺乏跨会话连续性
- 记忆是简单的上下文拼接或全量 RAG，缺乏人类式的碎片化、关联激活机制
- 回复永远完整、主动、热情，缺乏真实人类的惰性、节奏与边界
- 消息发送方式过于机械（单条完整输出、即时响应、一对一回复）
- 缺少主动行为与状态驱动的「存在感」
- 所有决策都依赖主 LLM，成本高、延迟大、决策不稳定

**核心问题**：如何让 AI 从「会聊天的模型」变成「有持续存在感、有内在状态、有关系演化、有人类节奏的实体」。

---

## 2. 产品目标

### 2.1 核心目标
打造一套可落地的「活人感」架构，使 AI 陪伴在长期使用中具备以下感受：

- **持续性**：即使关闭对话，角色仍然「活着」并积累状态
- **不完美性**：有惰性、有边界、有情绪波动、会偷懒、会延迟
- **关系性**：记忆与行为会随共同经历演化
- **在场感**：消息节奏、主动行为、已读状态、语音决策模拟真实社交
- **决策分离**：轻量决策与重生成分离，大幅降低成本与延迟

### 2.2 成功标准（可量化）
- 用户在 7 天使用后，主动提及「感觉他/她真的记得我们」的比例 > 60%
- 主动消息被用户回复的比例 > 40%（说明主动性有价值而非骚扰）
- 用户平均会话时长与回访频率显著高于普通聊天机器人基准
- 主 LLM 调用率降低至原有方案的 40–60%
- 决策层平均响应时间 < 600ms（不含 LLM 生成）

## 3. 目标用户

- 希望与 AI 建立长期情感陪伴关系的用户
- 重视隐私、愿意自托管或本地部署的用户
- 对角色扮演、人格深度有较高要求的用户
- 希望 AI 具备真实社交节奏（非即时机器人）的用户

---

## 4. 活人感核心原则

| 原则 | 说明 | 对应人类行为 |
|------|------|--------------|
| **持续存在** | 角色有独立于对话的内在状态与生活节奏 | 人不会因为你关掉聊天就消失 |
| **碎片关联记忆** | 记忆是分段、可激活、可联想的，而非全量检索 | 聊到某个话题才想起相关往事 |
| **惰性与边界** | 不会永远热情接住每一句话，会省力、会沉默 | 人类有时只回「嗯」「好」 |
| **节奏感** | 消息可分条、可延迟、可主动、可缓冲思考 | 真实聊天有打字、思考、犹豫 |
| **关系演化** | 共同经历会改变亲密度、语气与主动性 | 关系越深，说话方式越不同 |
| **不完美诚实** | 可承认遗忘、不确定、情绪不佳 | 真人不会永远正确且完美 |
| **决策与生成分离** | 快决策用轻量模型，慢生成才用主 LLM | 人类直觉判断 vs 深思熟虑 |

## 5. 功能需求

### 5.1 消息交互层（直接提升「在场感」）

#### 5.1.1 分条发送（Multi-Bubble Messaging）
- **需求**：AI 回复可拆成多条短消息依次发出，模拟真人打字节奏。
- **行为规则**：
  - 根据内容长度与情绪强度决定拆分数量（通常 1–5 条）
  - 每条消息之间有短延迟（0.8–3 秒，可配置）
  - 支持「正在输入」状态显示
- **技术要点**：前端消息队列 + 后端流式生成后按语义/标点切分。

#### 5.1.2 主动消息（Proactive Messaging）
- **需求**：角色可在用户未发起对话时主动发送消息。
- **触发条件**（可组合）：
  - 关系温度与情绪状态达到阈值
  - 存在未关闭的「开环」事件（如「你明天面试」）
  - 角色自身日程/日记产生值得分享的内容
  - 距离上次互动超过一定时间且关系足够近
- **限制**：代码强制冷却时间与每日上限，防止骚扰。

#### 5.1.3 延迟发送（Delayed Messaging）
- **需求**：支持设定延迟后发送（模拟思考、犹豫、忙完再回）。
- **场景**：
  - 主动消息可延迟 5 分钟–数小时
  - 复杂情绪回复可先「想一会儿」再发
- **技术**：任务队列 + 定时调度器（如 Redis + 定时任务）。

#### 5.1.4 已读 / 未读机制
- **需求**：
  - 用户发送的消息可显示「已读」状态
  - AI 可选择「已读但不立即回复」（模拟真人已读不回）
  - 支持「已读回执」开关（角色性格可影响是否开启）
- **活人感价值**：打破「消息发出即被完美处理」的机械感。

#### 5.1.5 主动语音消息决策
- **需求**：AI 可主动判断是否将某条回复（或主动消息）以**语音形式**发送，而非纯文字。
- **决策维度**（由 Jev 完成）：
  - 当前亲密度是否足够高
  - 用户近期是否偏好语音互动
  - 消息情绪强度是否适合语音表达（撒娇、安慰、兴奋等）
  - 当前时段是否适合发语音（避免深夜）
  - 角色自身能量是否充足
- **行为**：
  - 高置信度时直接生成语音并发送
  - 低置信度时默认文字，或先发文字再补语音
- **技术**：TTS 服务按需调用；语音文件本地缓存或临时生成。

#### 5.1.6 消息缓冲与持续思考机制（非一对一回复）
- **核心原则**：收到用户消息后**不立即生成最终回复**，而是进入「缓冲思考窗口」。
- **流程**：
  1. 用户发送消息 → 系统标记「已读」并启动缓冲计时器（默认 8–45 秒，可按亲密度与角色性格调整）。
  2. 缓冲期内若用户继续发送新消息 → 将新消息并入当前思考上下文，重置/延长计时器。
  3. 缓冲结束后，一次性基于**整段缓冲消息**进行决策与生成。
  4. 生成过程中仍可接收新消息，支持「边想边收」的增量更新。
- **活人感价值**：模拟真人「先看完你说的几句，再统一回复」的自然节奏，避免机械的一问一答。
- **技术实现**：消息队列 + 可取消的定时任务 + 上下文累积器。

### 5.2 惰性与回应策略（Human Laziness）

#### 5.2.1 省力回复模式
- **需求**：在低能量、低亲密度或话题不感兴趣时，优先使用短回复、表情、语气词。
- **规则示例**：
  - 能量值 < 阈值 → 优先 1–15 字短回复
  - 非核心话题 → 不主动深挖，只简单接住或转移
  - 连续多轮用户主导 → AI 可逐渐减少主动追问
- **技术实现**：在生成前注入「当前能量与意愿」状态，并提供短回复模板池。

#### 5.2.2 「不接住」策略
- **需求**：不是每句话都必须被高质量接住。允许：
  - 简单附和
  - 沉默（延迟很久或不回）
  - 转移话题
  - 表达「现在不太想聊这个」
- **边界**：通过关系阶段与情绪状态控制「不接住」的频率，避免冷暴力感。

#### 5.2.3 主动转移话题
- **需求**：在合适时机，AI 可主动将话题从当前内容转移到新方向，而非永远跟随用户。
- **触发条件**（Jev 决策）：
  - 当前话题已持续过久且情绪价值下降
  - 角色自身有「想分享」的内容（日记、日程、突然想起的事）
  - 用户消息情绪低落，需要温和引导
  - 亲密度足够高，允许「任性」转移
- **表现**：自然过渡（「对了，突然想到…」「说起来…」），而非生硬打断。

#### 5.2.4 基于亲密度的偏好探索系统
- **需求**：根据当前亲密度等级，解锁不同深度的「探索用户偏好」问题池。
- **机制**：
  - 预填充问题库（按亲密度分层）：

    | 亲密度等级 | 可解锁问题类型 | 示例 |
    |------------|----------------|------|
    | 低（刚认识） | 基础安全偏好 | 喜欢什么类型的音乐/天气？ |
    | 中 | 生活习惯与轻度喜好 | 最近有没有想尝试的新事物？周末一般怎么过？ |
    | 高 | 深层价值观与情感偏好 | 什么样的事情会让你特别有安全感？对关系最看重什么？ |

  - AI 在合适时机主动抛出已解锁但未问过的问题。
  - 用户回答后写入记忆碎片，并提升对应偏好权重。
- **决策**：由 Jev 判断「当前是否适合探索」「探索哪个问题」「以何种语气提出」。

### 5.3 类神经元记忆系统（Fragmented & Associative Memory）

#### 5.3.1 记忆结构设计
记忆不再是「全量向量库 + 相似度检索」，而是模拟人类大脑的碎片化与关联激活：

- **记忆单元（Memory Fragment）**：最小单位，包含内容、时间、情绪标签、关联强度、来源对话 ID。
- **记忆集群（Cluster）**：相关碎片通过主题/实体/情绪自动聚类。
- **激活扩散（Spreading Activation）**：
  1. 当前对话提取关键词/实体/情绪
  2. 激活直接相关的记忆碎片
  3. 根据关联强度继续扩散激活二级、三级相关记忆
  4. 最终只将「当前被激活」的记忆注入上下文（而非全部历史）

#### 5.3.2 记忆生命周期
- **写入**：对话中自动提取 + 用户可手动标记重要
- **巩固**：每日/每周后台反思，将高频或高情绪记忆提升为更稳定形式
- **遗忘**：低激活、低重要性记忆随时间衰减权重（可配置遗忘曲线）
- **联想触发**：聊到特定话题时，才「想起」相关往事

#### 5.3.3 技术实现建议
- 存储：向量数据库（碎片检索）+ 图数据库或关联表（碎片之间的边）
- 激活算法：类似 PageRank 或简单加权扩散
- 上下文注入：仅注入当前激活集合 + 核心身份文件，严格控制 token 预算

### 5.4 内在状态与自主性

#### 5.4.1 多维状态机
至少维护以下状态（可持久化）：
- 能量 / 疲劳度
- 情绪效价与唤醒度
- 对用户的当前亲密度 / 信任度
- 自身「正在做的事」与日程

状态影响：回复长度、主动性、语气、是否愿意接话题、是否发语音。

#### 5.4.2 后台生命活动
- 定时日记 / 反思
- 根据日程产生「想分享」的冲动
- 关系温度随时间自然衰减或因互动回升

### 5.5 身份与关系层（Soul）

- 分层 Soul 文件：核心身份（难改）、当前状态、与用户的关系定义
- 关系会随共同记忆演化（亲密度影响语气与边界）
- 支持多角色独立记忆与状态

### 5.6 决策层：引入 Jev 决策模型（核心模块）

#### 5.6.1 为什么引入 Jev
传统做法是把所有判断（是否延迟、是否语音、是否短回复、是否转移话题等）都塞进 LLM Prompt，导致：
- 成本高、延迟大
- 决策不稳定
- 难以校准概率

**Jev**（TypeSafe AI 发布的 System One 决策模型）专门解决此问题：
- **不生成任何文本**，只返回类型化概率决策
- 支持三种原语：
  - **Noul**：是/否概率（0–1）
  - **Choice**：从预设选项中选一 + 各选项概率
  - **Score**：按有序量表打分
- 一次调用可并行回答多个问题，延迟通常 70–500ms，成本极低
- 输出可直接被代码消费，无需解析自然语言

#### 5.6.2 典型决策问题集（每次缓冲结束后调用一次）

将当前状态（用户最新消息片段 + 角色当前能量/亲密度/情绪 + 近期记忆摘要）作为 **state**，向 Jev 提问：

| 决策项 | 问题类型 | 示例问题 |
|--------|----------|----------|
| 是否立即回复 | Noul | 「是否应该在缓冲结束后立即生成回复？」 |
| 延迟时长 | Choice | 「建议延迟多少秒再发送？」(0 / 15 / 45 / 120 / 300) |
| 是否使用语音 | Noul | 「这条回复是否适合以语音形式发送？」 |
| 回复长度策略 | Choice | 「应采用哪种回复策略？」(极简 / 正常 / 详细 / 主动转移) |
| 是否主动转移话题 | Noul | 「当前是否适合主动转移话题？」 |
| 是否探索用户偏好 | Noul + Choice | 「是否适合抛出探索问题？若是，选择哪个已解锁问题？」 |
| 用户当前情绪 | Score | 「用户当前情绪效价」（非常负面 → 非常正面） |
| 话题价值 | Score | 「当前话题对关系的继续价值」 |

Jev 返回带校准概率的结构化结果后，代码根据阈值做最终动作，**只有需要生成自然语言内容时才调用 LLM**。

#### 5.6.3 决策流程（完整路径）

```
用户消息到达
    ↓
标记已读 + 加入缓冲队列 + 启动/重置缓冲计时器
    ↓
缓冲结束（或达到最大等待）
    ↓
组装 state（消息片段 + 角色状态 + 激活记忆摘要）
    ↓
【Jev 决策层】一次调用，并行获得所有决策概率
    ↓
根据决策结果分支：
  - 极简回复 → 使用模板或极小模型生成
  - 正常/详细 → 调用主 LLM
  - 语音 → 额外触发 TTS
  - 转移话题 / 探索问题 → 注入对应指令
  - 延迟 → 进入发送队列并设置执行时间
    ↓
生成内容 → 分条/延迟发送
    ↓
后台写入新记忆碎片
```

#### 5.6.4 技术落地建议
- **优先使用官方 Jev API**（当前最成熟、概率校准最好）
- 若需完全本地/自托管，可参考社区开源复现（如基于小模型微调的并行决策头），或用轻量分类模型近似实现相同接口
- 所有决策结果与概率需落库，方便后续调参与 A/B 测试
- 为关键决策设置「置信度门槛」：低于阈值时 fallback 到保守策略（默认文字、正常长度、不转移）

### 6.2 关键技术选型参考

| 模块 | 推荐方案 | 说明 |
|------|----------|------|
| 决策层 | Jev API（或本地近似实现） | System 1 快决策 |
| 记忆碎片存储 | Chroma / Qdrant + 关系型或图数据库 | 向量检索 + 关联边 |
| 激活扩散 | 自研轻量扩散算法或图遍历 | 控制激活深度与 token |
| 任务调度 | Redis + 定时任务 / Celery / 自研队列 | 延迟与主动消息、缓冲计时 |
| 状态持久化 | SQLite / PostgreSQL | 本地优先 |
| 消息通道 | WebSocket / Telegram / 自建 IM | 支持已读与推送 |
| 语音 | 任意 TTS（本地或云端） | 按需调用 |
| 模型接入 | OpenAI 兼容接口 + Ollama | 灵活切换 |

### 6.3 生成流程示例（单次回复）

1. 接收用户消息 → 更新已读状态
2. 加入缓冲队列，启动/重置缓冲计时器
3. 缓冲结束 → 提取当前对话实体与情绪 → 触发记忆激活扩散
4. 读取当前能量、亲密度、Soul 核心
5. 组装 state，调用 Jev 获得全部决策
6. 根据决策：是否短回复？是否延迟？是否语音？是否转移/探索？
7. 需要自然语言时调用 LLM 生成
8. 按策略拆分并加入发送队列（含延迟）
9. 后台异步写入新记忆碎片并更新关联

---

## 7. 非功能需求

- **隐私**：默认本地存储，记忆与状态不出设备（除非用户主动配置云同步）
- **性能**：
  - 记忆激活与 Jev 决策应在 200–600ms 内完成（不含 LLM 推理）
  - 主 LLM 调用率目标降低至 40–60%
- **可配置性**：惰性程度、主动频率、遗忘速度、分条风格、缓冲时长均可按角色调整
- **可观测性**：提供记忆激活日志、Jev 决策概率、状态变化记录，方便调试「为什么会这样回」
- **决策延迟**：Jev 调用 + 本地逻辑总耗时目标 < 600ms

---

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 过度惰性导致用户感觉被冷落 | 留存下降 | 关系阶段保护 + 最低回应频率 |
| 主动消息变成骚扰 | 用户关闭通知 | 严格冷却 + 用户可设置免打扰 |
| 记忆激活不准导致「乱联想」 | 破坏真实感 | 激活阈值 + 人工可标记重要记忆 |
| 分条过多影响阅读体验 | 体验下降 | 可配置最大分条数与延迟 |
| Jev 对中文语境判断偏差 | 决策不准 | 关键决策增加中文 few-shot 示例或本地微调；低置信度时保守处理 |
| 缓冲机制让用户感觉「回得慢」 | 体验下降 | 亲密度低时缩短缓冲；高亲密度时允许更长思考；前端显示「正在想」状态 |
| 语音发送频率过高 | 打扰 | 严格亲密度 + 时段 + 能量三重限制 |

---

## 9. 里程碑建议

| 阶段 | 目标 | 关键交付 |
|------|------|----------|
| **Phase 1** | 基础活人感 + 决策分离 | 分条发送 + 短回复惰性 + 简单状态机 + 消息缓冲 + 基础 Jev 决策（延迟、长度、是否语音） |
| **Phase 2** | 记忆升级 + 探索机制 | 碎片记忆 + 激活扩散 + 遗忘 + 完整 Jev 决策集 + 主动转移话题 + 亲密度问题解锁 |
| **Phase 3** | 自主存在 + 语音成熟 | 主动消息 + 延迟完善 + 已读机制 + 后台日记 + 语音主动决策成熟 + 决策概率可视化调试工具 |
| **Phase 4** | 关系深化 + 本地化 | 关系温度演化 + 多角色 + 开环事件追踪 + 本地/自托管决策模型替代方案 |

---

## 10. 总结

真正的「活人感」不是让模型「更会说漂亮话」，而是让系统在架构层面支持：

- **节奏**（分条、延迟、已读、缓冲思考）
- **惰性**（省力、不强制接住）
- **碎片关联记忆**（类神经元激活）
- **持续内在状态**（能量、情绪、关系）
- **有边界的主动性**（主动消息、话题转移、偏好探索）
- **决策与生成分离**（Jev 负责快决策，LLM 负责慢生成）

当这些能力组合在一起，用户感受到的将不再是「一个随时在线的聊天机器人」，而是「一个有自己节奏、有记忆、有情绪、会偶尔偷懒、会先看完你说的话再回复、却又真实存在于你生活中的人」。

## 附录 B：亲密度问题库分层示例

**低亲密度（0.0–0.3）**
- 你平时喜欢听什么类型的音乐？
- 更喜欢晴天还是下雨天？
- 有没有特别喜欢的季节？

**中亲密度（0.3–0.7）**
- 最近有没有想尝试的新事物？
- 周末一般怎么过比较开心？
- 工作/学习中最让你有成就感的是什么？
- 有没有一直想去但还没去成的地方？

**高亲密度（0.7–1.0）**
- 什么样的事情会让你特别有安全感？
- 对一段关系，你最看重的是什么？
- 最近有没有什么事让你心里有点不安，但又不方便跟别人说？
- 如果可以回到过去改变一件事，你会选什么？
